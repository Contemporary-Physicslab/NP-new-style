# Data Management

Als wetenschapper is het belangrijk om alle data en de verwerking daarvan netjes te bewaren: andere wetenschappers moeten in staat zijn om jouw resultaten op een zelfde manier te verwerken en daarmee te komen op gelijke conclusies. Maar ook jij wilt je data of je code misschien later nog een keer gebruiken - dat moet niet veel werk zijn. Daarbij is er altijd het risico dat je laptop kwijt raakt, of dat je harde schijf stuk gaat: je moet dus een backup van je werk hebben.

Ook als student is het fijn als je snel en eenvoudig je werk terug kunt vinden. Dat is een uitdaging omdat je bij elk vak, elk semester, elk jaar nieuwe powerpoints, code en andere bestanden krijgt. 

Hieronder volgen een aantal standaarden, tips en tricks om vanaf dag 1 je werk overzichtelijk te bewaren. 

## Persoonlijke datamanagement:

Maak voor je studie een map aan, bijvoorbeeld op de structuur gegeven in {numref}`fig-datamanagement`

```{figure} Figures/folderstructure.png
:width: 90%
:name: fig:datamanagement

Voorbeeld van een bestandenstructuur voor je hele bachelor. 
```

- Je downloadfolder en bureaublad is geen werkmap: verwijder regelmatig bestanden uit je downloadfolder.
- Organiseer je files in een hiërarchische structuur zoals hierboven weergegeven. Houd als vuistregel aan: 10 bestanden per folder, tenzij al die bestanden van het zelfde type zijn. Als een map te vol raakt is er vaak een subcategorie die een individuele map kan hebben.
- Maak regelmatig een backup, dat kan door bestanden in OneDrive te zetten - of op een externe hardeschijf of USB.
- Je laptop zal regelmatig toch rommelig aandoen. Neem af en toe de tijd om je laptop op te ruimen.

## Datamanagement in de wetenschap:

Persoonlijke datamanagement is fijn voor jezelf, maar in wetenschappelijk onderzoek is georganiseerde data essentieel. Elke onderzoeksgroep heet een eigen werkwijze, maar goede wetenschappelijke datamanagement bevat onder anderen gebruik van één environment waarin gewerkt wordt (Pixi voor Jupyter Notebooks), het bijhouden van oude versies van code (Version control in Git) en consequente naamgeving van bestanden. Om deze methoden te delen met elkaar wordt een Readme bestand in de map gezet en staat in alle code meta-data die aangeeft wat stukken code doen.

## Experimentele data:

In de practica ga je data verzamelen en bewerken. Hierbij is het belangrijk dat je altijd de originele onbewerkte data bewaart. Als je data in excel verzameld hebt, sla het originele bestand dan op met de naam 'raw' en kopieer dit bestand voordat je er iets mee doet. Voeg dan ook een Readme bestand toe om aan je medestudenten te laten weten dat ze dit 'raw' bestand niet moeten bewerken.

## Naamgeving:

De naam van je bestanden moet duidelijk aangeven wat het bestand, wanneer het aangemaakt en welke versie het is. Om deze naamgeving consequent te houden kan je de gebruikte conventies in het Readme bestand opslaan. Dingen om in de naamgeving te verwerken zijn: De datum, je naam, je studentnummer en de versie.
